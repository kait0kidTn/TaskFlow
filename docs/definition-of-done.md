

\# TaskFlow — Technical Definition of Done



A task is considered Done when all applicable criteria below are satisfied.



\## Code quality

\- \[ ] The change solves the agreed requirement.

\- \[ ] Code is readable and follows the project's conventions.

\- \[ ] No unrelated changes or unnecessary duplication are introduced.

\- \[ ] Sensitive information and database credentials are not committed.



\## Automated testing

\- \[ ] Relevant automated tests are added or updated.

\- \[ ] All automated tests pass locally.

\- \[ ] Invalid inputs and important failure cases are considered.



\## Integration

\- \[ ] The application starts successfully.

\- \[ ] API behavior is verified for the changed functionality.

\- \[ ] Database operations are parameterized where applicable.

\- \[ ] The GitHub Actions CI workflow passes.



\## Review and delivery

\- \[ ] Another team member reviews the change when possible.

\- \[ ] The change is committed with a meaningful message.

\- \[ ] Known limitations or technical debt are documented.



\## Evidence

\- \[ ] Test results are recorded.

\- \[ ] Relevant screenshots or CI results are saved for the project report.
